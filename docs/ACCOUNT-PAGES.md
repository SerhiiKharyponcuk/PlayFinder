# Вхід та обране

Обидві сторінки використовують наявні Firebase Auth і Firestore. Нового способу входу або окремої бази обраного немає.

## Де що змінювати

| Що потрібно змінити | Файл |
| --- | --- |
| Розмітка форми, вкладки, поля, блок акаунта | `login.html` |
| Вигляд форми на комп’ютері й телефоні | `src/scss/pages/_login.scss` |
| Перемикання входу/реєстрації, показ пароля, повідомлення, вихід | `src/js/pages/login.js` |
| Виклики Firebase для авторизації | `src/js/services/auth-service.js` |
| Розмітка обраного, завантаження та порожнього списку | `favorites.html` |
| Сітка й мобільні картки обраного | `src/scss/pages/_favorites.scss` |
| Завантаження списку, лічильник і видалення картки | `src/js/pages/favorites.js` |
| Читання та запис обраного в Firestore | `src/js/services/favorites-service.js` |
| Сердечка в каталозі й деталях гри | `src/js/features/favorites.js` |
| Спільна шапка, кнопки, футер і фокус клавіатури | `src/scss/components/_account.scss` |

Стилі підключені через `src/scss/main.scss`, сторінки — через `src/main.js`. Після `npm run build` Vite додає CSS і JavaScript у збірку для GitHub Pages.

## Як поводяться сторінки

У вході вкладка визначає, який метод викликати: `authService.login()` чи `authService.register()`. Це одна форма, тому Enter надсилає саме вибрану дію. Вкладки також перемикаються стрілками клавіатури. Під час запиту поля та кнопки блокуються, щоб не надсилати повторні запити.

Після входу форма змінюється на блок акаунта з email, переходом до обраного та виходом. Тексти помилок Firebase перекладаються на зрозумілі повідомлення.

В обраному `listIds()` отримує збережені RAWG ID. Деталі завантажуються по чотири гри одночасно. Картки з’являються до завершення перевірки цін; ціни беруться з наявного сервісу та його кешу. Якщо одна гра не завантажилася, решта залишаються видимими, а лічильник показує, скільки вдалося відкрити.

Лише після успішного видалення з Firestore картка зникає й змінюється лічильник. Якщо видалена остання гра, з’являється підказка перейти до каталогу. Під час зміни користувача старі відповіді не можуть замінити його новий список.

Окремо оформлено завантаження, стан без входу, порожнє обране, недоступність сервісу та помилку з кнопкою повторної спроби. На телефоні картки розташовані горизонтально; обмеження кількості карток з головної сторінки тут не застосовуються.
