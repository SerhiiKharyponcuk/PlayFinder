# Урок: покращуємо пошуковий запит

## Мета на одну годину

Навчити пошук розуміти `GTA 5`, `GTA V` та `GTAV`, прибирати зайві пробіли й зберігати інші назви без підміни гри. Наприкінці уроку всі дев'ять навчальних прикладів мають показувати «ГОТОВО».

Підказки під час введення, debounce, керування списком клавіатурою та сортування за релевантністю — окремий наступний урок. Сьогодні пошук залишається після Enter. Основна робота розрахована на 45 хвилин, останні 15 — запас на питання та перевірку.

## Що вже підготовлено

- Обидві форми, комп'ютерна й мобільна, викликають одну функцію `normalizeSearchQuery`.
- Функція вже підключена, але зараз лише прибирає пробіли на початку й наприкінці. Обробку внутрішніх пробілів і скорочень ви напишете на уроці.
- Перехід у каталог, параметр `q`, збереження фільтрів і скидання сторінки до першої працюють.
- Команда `npm run lesson:search` показує ввід, поточний результат та очікуваний результат. Вона не відкриває браузер, не викликає RAWG/CheapShark і не витрачає ліміти.
- На початку готові 4 із 9 прикладів. Позначка «ЗАВДАННЯ» для решти очікувана: це робота уроку. Команда показує прогрес; вона не замінює автоматичні тести.

Додатково підготовлений [локальний об'єкт із 10 000 ігор](SEARCH-DATA.md) для вашої `generateAliases`. Передавати в неї треба `SEARCH_GAMES_LIST`; це масив із полями `name` і `slug`. Дані можна використати на уроці без запитів до API. Обробку пробілів ви вже дописали: у поточному коді готові 5 із 9 прикладів; нижче залишений початковий порядок уроку.

| [search-query.js](../src/js/features/search-query.js), `normalizeSearchQuery(value)` | Основний файл уроку: змінюємо підготовку `query`, додаємо відповідність скорочень повній назві перед `return`. |
| [search.js](../src/js/features/search.js), `initSearch()` | Читаємо, щоб побачити підключення функції до обох форм. Перехід у каталог вже готовий. |

`src/main.js`, ключі, ціни, кеш і шаблони карток для цього уроку змінювати не потрібно.

## 0–10 хвилин: знайти код і перевірити заготовку

1. Після отримання змін виконати `npm install`, потім `npm run dev`. Відкрити головну за адресою, яку надрукує Vite, зі шляхом `/PlayFinder/`.
2. Ввести `Portal 2` та натиснути Enter. Відкриється `games.html`, а в адресі буде `q=Portal+2`.
3. Відкрити поруч `search-query.js` і `search.js`. Знайти виклик `normalizeSearchQuery` у формі.
4. У другому терміналі виконати `npm run lesson:search`. Побачити 4 готові приклади та 5 завдань.
5. Домовитися: зміни пишемо всередині `normalizeSearchQuery`. Вона повертає рядок, а не масив ігор, Promise чи відповідь API.

## 10–25 хвилин: прибрати зайві пробіли

1. У рядку створення `query` залишити перетворення значення на рядок і `trim()`.
2. Додати заміну послідовностей пробільних символів одним пробілом. Підказка: `replace`, регулярний вираз `/\s+/g` і рядок `' '`.
3. Виконати `npm run lesson:search` ще раз. Приклад із `Grand   Theft\tAuto   V` має перейти у «ГОТОВО»: тепер готові 5 із 9.
4. Перевірити, що порожній рядок залишається порожнім, а апостроф у `Baldur's Gate 3` не зникає.

Якщо цей крок забрав багато часу, завершити його й перевірки. Скорочення можна перенести на наступний урок.

## 25–45 хвилин: розпізнати скорочення

1. Перед функцією створити об'єкт відповідностей скорочення → повна назва. Назвати його `SEARCH_ALIASES`.
2. Додати два ключі: `gta5` та `gtav`. Значення обох — `Grand Theft Auto V`.
3. Усередині функції створити окремий ключ для перевірки: взяти `query`, перевести в нижній регістр і прибрати пробіли. Підказки: `toLowerCase()` та `replace(/\s/g, '')`.
4. Перевірити, чи є цей ключ власною властивістю об'єкта. Підказка: `Object.hasOwn(SEARCH_ALIASES, key)`.
5. Якщо ключ є, повернути його повну назву. Якщо немає, залишити `return query`.
6. Запустити навчальну команду: очікуємо 9 із 9.

Нижній регістр і видалення пробілів використовуємо тільки для ключа перевірки. У звичайній назві зберігаємо регістр, апострофи й номер. `Grand Theft Auto IV` має залишитися четвертою частиною. Не використовуємо `includes('gta')` або перший знайдений результат API.

## 45–60 хвилин: запас і перевірка сайту

1. На головній ввести `GtA 5` та натиснути Enter. В адресі каталогу має бути `q=Grand+Theft+Auto+V`, у полі — повна назва.
2. У каталозі вибрати один фільтр, наприклад платформу PC. Виконати пошук: параметр платформи має залишитися в адресі. Врахувати, що активні фільтри можуть звузити результат до нуля.
3. Перевірити мобільну форму через адаптивний режим браузера: вона використовує ту саму функцію.
4. Перевірити порожній пошук: каталог відкривається без `q`, а вибрані фільтри зберігаються.
5. Виконати `npm test` та `npm run build`.

Назви й порядок реальних результатів залежать від RAWG та фільтрів. На цьому уроці перевіряємо правильний запит; не обіцяємо, що конкретна гра буде першою. Налаштування релевантності залишене для наступного заняття.

## Якщо щось не працює

| Що бачимо | Що перевірити |
| --- | --- |
| `query` змінений, а результат залишився старим | Перевірити, яке значення повертається через `return`. Зберегти файл і повторити команду. |
| Спрацьовує `GTAV`, але не `GTA V` | У ключі перевірки треба прибрати пробіли. |
| Спрацьовує `gta 5`, але не `GtA 5` | Перевести ключ перевірки в нижній регістр. |
| Змінилася назва іншої гри | Повернути початковий `query` для невідомих ключів; не застосовувати частковий збіг. |
| Дев'ять прикладів готові, але карток немає | Перевірити повідомлення каталогу, активні фільтри та налаштування RAWG. Це окремо від функції обробки рядка. |
| Пошук жанру чи видавця не дає очікуваного | Поточна форма шукає назву гри. Жанр обирається фільтром; окремий пошук видавців ще не підключений. |

## Де лежить основа для наступного уроку

У `index.html` і `games.html` уже є `#searchResults` та `#searchResultTemplate`. Вони поки не заповнюються. Стилі підказок — у [\_games.scss](../src/scss/pages/_games.scss), блоки `.search-results` та `.search-result`.

Для майбутніх підказок треба окремо навчитися отримувати невеликий список ігор без цін, показувати його та обробляти затримку/скасування старого запиту. Для цього вже є `gamesService.getGames(params, { withPrices: false, signal })` і `searchRelevance` у RAWG-провайдері. Поки ці виклики у форму не додаємо.

Нормалізатор цього уроку працює з текстом користувача. Зіставлення назв RAWG і CheapShark у `services/game-matching.js` відповідає за ціни й залишається окремою логікою.
