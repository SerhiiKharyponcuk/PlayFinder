# Швидший показ ігор і лоадери

Раніше головна чекала два списки RAWG, пошуки відповідностей у CheapShark і пакет
цін. Через захисний інтервал черги 1,2 с готові обкладинки могли довго не показуватися.

Тепер HTML містить видимі скелетони. Щойно RAWG готовий, показуємо картки з
«Шукаємо ціну…». Пізніше оновлюємо тільки блок ціни: обкладинка, посилання,
фокус і сердечко Firebase не перемальовуються. Популярні не чекають нових релізів.
Детальна сторінка також показує опис раніше, а потім оновлює лише таблицю цін.

## Де писати код на уроці

| Що | Файл |
| --- | --- |
| Ранній показ RAWG | `src/js/services/games-service.js`: `onGames`, `onList`, `onGame` |
| Індикатор ціни, повідомлення й кнопка повторення | `src/js/components/game-list.js` |
| Показ карток / оновлення тільки ціни | `src/js/components/cards.js`: `renderGames`, `updateGamePrices` |
| HTML блоку ціни | `src/templates/game-card.hbs`: `priceLoading`, `.game-card__pricing` |
| Стилі скелетонів і спінерів | `src/scss/components/_loading.scss` |
| RAWG-кеш | `src/js/api/providers/rawg.js`: `RAWG_CACHE` |
| Кеш і ліміти цін | `src/js/api/cheapshark-client.js`: `SHARK_CACHE` |

Головна `pages/home.js` передає `onList` у сервіс, каталог `pages/games.js` —
`onGames`. Callback отримує ранні дані RAWG; Promise сервісу повертає кінцеві
дані з цінами. Старий код `await gamesService.getGames(...)` лишається робочим.
Обидва списки головної все ще об'єднуються для одного пакета пропозицій.

## Кеш і помилки

- Списки RAWG зберігаються на 10 хвилин, описи — на годину.
- Пошуки CheapShark — на добу, ціни — на 30 хвилин; дивись `PRICE-CACHE.md`.
- localStorage різний для localhost і GitHub Pages. Пуш не очищує його.
- Ключ RAWG не записується в ключах/значеннях цього кешу. Це не змінює того,
  що `VITE_*` налаштування браузерного застосунку доступні його JavaScript.
- Недоступна ціна не означає нуль. Кнопка «Оновити ціни» повторює лише невдалі
  ціни, не видаляє успішний кеш і не прибирає картки.
- Під час паузи CheapShark кнопка показує очікування й заблокована. Автоматичних
  повторних запитів немає. Після паузи кнопку можна натиснути.
- «Немає пропозицій» і мережевий збій — різні стани. Не підставляємо ціну DLC
  або іншої гри, навіть коли потрібного товару немає в CheapShark.

## Права колонка

API повертає пропозиції магазинів, тому одна гра повторювалася кілька разів.
Тепер беремо одну сторінку до 60 пропозицій одним запитом, групуємо за `gameID`
і лишаємо найдешевшу пропозицію кожного товару. Різні видання з різними ID не зливаємо.
Це найкращі знайдені пропозиції цієї сторінки API, не гарантований мінімум усього каталогу.

## Перевірка

При першому відкритті: скелетони → картки з індикаторами ціни → суми.
При повторному відкритті чинний кеш скорочує очікування.
У `npm test` повільні відповіді моделюються без мережі й витрати лімітів API.
Рух лоадерів вимикається для `prefers-reduced-motion`.

## Чому лоадер можна було не помітити

Локальні зміни з лоадерами потрібно закомітити й запушити. Після цього дочекайся
зеленого запуску `Deploy to GitHub Pages` у вкладці Actions. Наявність змін у
VS Code сама по собі не змінює опублікований сайт. З чинним кешем лоадер також
може зникати швидко — не додаємо штучних секунд очікування.

Тепер на головній, у каталозі, деталях та обраному є спільний індикатор у кутку
екрана. Він не заважає натискати готові картки. Підпис змінюється з
«Завантажуємо ігри…» на «Перевіряємо ціни ігор…». Індикатор закривається,
коли всі завдання завершилися, включно з помилками. Якщо CheapShark недоступний,
після завершення лишається повідомлення й кнопка повторення біля секції.

Керування — `src/js/components/site-loader.js`: `begin()` повертає завдання,
`update()` змінює підпис, `finish()` завершує **саме це** завдання. Нове завдання
обов'язково завершуйте у `finally`. HTML `#siteLoader` є в самих сторінках,
тому індикатор не потрібно створювати після відповіді API.

## Що зменшили для швидкого завантаження

| Ресурс | Було | Стало |
| --- | ---: | ---: |
| Фон головної | PNG 2 170 268 байтів | WebP 132 932 байти; мобільний 20 854 байти |
| Фон «Про нас» | PNG 1 986 382 байти | WebP 131 724 байти; мобільний 18 802 байти |
| JavaScript, необхідний для показу головної | приблизно 436 КБ | приблизно 174 КБ |

Останній рядок — розмір обов'язкових JS-файлів production-збірки до стиснення,
без картинок і додаткового Firebase. Це не обіцянка конкретної кількості секунд:
час відповіді RAWG/CheapShark і швидкість з'єднання можуть відрізнятися.

- HTML використовує `srcset`/`sizes`: браузер вибирає розмір WebP. Оригінальні
  PNG залишені в `public/images` для редагування, сторінки їх не завантажують.
- Vite компілює `.hbs` через `scripts/handlebars-plugin.js`. Редагуйте ті самі
  файли в `src/templates`. Імпорт тепер має `?template`; браузер отримує лише
  Handlebars runtime, а не повний компілятор. Екранування `{{...}}` збережене.
- Firebase для сердечок завантажується окремим `import()`. За відсутності його
  конфігурації SDK взагалі не потрібний каталогу. За наявності — читається у фоні,
  без блокування показу RAWG. Натискання сердечка чекає початкового читання обраного.
- RAWG і CheapShark використовують попередній кеш і спільну чергу. Перезапуск
  сторінки не запускає всі пошуки цін заново. Захисний інтервал запитів не скорочували.

Шаблони, escaping, повільні ціни, кілька одночасних завдань та закриття лоадера
при помилці перевіряє `npm test`, без запитів до справжніх API.
